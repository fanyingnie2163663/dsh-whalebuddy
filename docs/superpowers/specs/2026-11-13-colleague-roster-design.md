# 同事花名册（公共协作层）· 设计

- 日期：2026-11-13
- 状态：**已批准**（2026-11-13 批准，定于谷时段 2026-11-14 01:00 开工）
- 决策：走方案 A（公共花名册，全员注入）；B（工单队列）与 C（运行时 A2A）留作以后
- 相关：[2026-11-09-whalebuddy-design.md](2026-11-09-whalebuddy-design.md)

## 1 意图

现在两个同事之间的交接（`designs/<slug>/BRIEF.md`）是老板**用手搬的**。她们各自清楚"我是谁"，但不清楚"还有谁、谁会接、我该把东西交给谁"。

根源不是缺通道，是缺**公共的职责图谱**。老板要的三件事——清楚职责、知道找谁、知道怎么交接——都是**知识**，不是管道。

## 2 目标 / 非目标 / 反目标

**目标**
1. 每个同事开场就知道：有哪些同事、各自吃什么、交什么、不管什么。
2. 任务进来时，能判断"这是我干还是该找谁"，并说得出理由。
3. 交接有统一格式，落点固定，老板能读。

**非目标**
- 不做自动派活（谁干什么仍由老板或她自己判断）。
- 不做消息队列（`_shared/outbox/`）——留口子，不做。
- 不做运行时 A2A（起对方会话、等待返回）。
- 不做跨模型路由（只保证格式不为它设障）。

**反目标**（做到也算失败）
- 花名册变成"第二个记忆库"：把私人偏好、你的私事、默契塞进去。
- 同事开始替别人做决定（"我顺手把配色定了"）。
- 花名册宽到没人读（硬上限 700 字）。

## 3 约束

- 反目标第 3 条（同事不互读私有记忆）**不改**。花名册是显式公共层，与 `memory/` 物理分离，只放**职能与协议**。
- 现有注入只有一段 `shared`（「关于你」，150 字）——插槽现成，容量不够。
- 只改插件内部，不 patch DSH 本体。

## 4 方案

**A（选中）**：`_shared/roster.md` + 注入新增「同事」一段。
- 成本：一个文件 + `inject.js` 一段 + `index.js` 读一行。
- 代价：靠自觉，她可能不查。用"开场必读"的位置和硬上限缓解。

**B（缓）**：加 `_shared/outbox/` 工单文件与回执。
- 只有在 A 跑一段、发现"交接丢了/没人接"时才值得。

**C（缓）**：插件注册 `colleague_ask` 工具，真起会话。
- 每次转述都是一次模型调用；要动 agents API；要防死锁和互相踢皮球。

> 选 A 的逻辑：**目标是知识，通道是过度设计。**

## 5 设计

### 5.1 文件

`~/.dsh/whalebuddy/_shared/roster.md`，全员同一份。格式固定三段：

```md
## 同事
- 逆戟 · 视频：吃 BRIEF.md，出成片（秒数/帧率/大小）。不管审美定调、配色、文案。
- 一角 · 美术：吃选题与参考片，出 BRIEF.md。不管渲染、配乐、导出。
- 小白 · 日常：陪伴与杂事。不管影像与设计。

## 怎么找
- 要"长什么样" → 一角
- 要"做出来" → 逆戟
- 拿不准 → 先问老板，别自己认领

## 怎么交接
- 一切走文件，落在 designs/<slug>/：BRIEF.md（一角→逆戟）、回执（逆戟→一角，写在 BRIEF 的「阻碍」节）
- 交接不写进任何人的私有记忆
```

### 5.2 注入

`inject.js` 的 `assembleMemory` 增加一段 `### 同事`，位置在「身份」之后、「默契」之前——她先知道自己在哪张桌上，再知道跟谁怎么处。

- 新预算键 `roster`，默认 **700 字**（约 350 token），超出按句子边界截断（复用 `truncateToBudget`）。
- `index.js` 读 `_shared/roster.md` 并传进来；文件不存在就整段不渲染（不出现空标题）。

### 5.3 边界规则：硬边界 + 显式例外

花名册里的「不管」**写死**：接不归自己的活要停下来说一句，不能默默做。

但留一个出口：**临时接可以，必须在回复里点明"这不是我的岗，我临时接"**，并在收工时把这条写进日志。理由：
- 全禁会在对方缺席时死锁；
- 全放会让人慢慢越界，岗就没了；
- 显式例外两头都防。

### 5.4 交接格式

沿用已有的 [BRIEF-format.md](../../../designs/BRIEF-format.md)（四段 + 阻碍栏），不新增格式。花名册只说**落点**和**方向**，格式细节留在那份文档里。

### 5.5 为跨模型留的口子

花名册**只写能力与契约，不写模型名、不写插件名**。职位描述以"吃什么 / 出什么 / 不管什么"表达——换模型、换供应商、同事之间异构，都不需要改这张表。

## 6 改动清单

| 文件 | 改动 |

| `lib/inject.js` | 新增 `roster` 预算键；`assembleMemory` 增加「同事」段 |

| `test/inject.test.js` | 覆盖：有/无花名册、超预算截断、空标题不渲染 |
| `~/.dsh/whalebuddy/_shared/roster.md` | 新建，写三行 |
| 三个同事的 `hot.md` | 各加一行指向花名册 |

## 7 验收

- [ ] 开场注入里能看到「同事」段，且在三行同事信息内说清"找谁"
- [ ] 删掉 roster.md，注入正常、无空标题
- [ ] 700 字上限生效，截断落在句号上
- [ ] 私有记忆没被合并进公共层（检查：roster 里不出现任何同事的私房默契）
- [ ] `npm test` 全绿

## 8 留给实现者

- 「同事」段的标题用「同事」还是「花名册」：我取「同事」，更短，和她自己的身份呼应。
- 是否在 roster 顶部加一行"这是公共契约，不是你的记忆"：倾向加，防止模型把公共层当私事。
- 小白没有岗位（role 为空），花名册里先按「日常」写，等她说清楚再改。
